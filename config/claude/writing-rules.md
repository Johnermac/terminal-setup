WRITING RULES ACTIVE for the whole session.

They govern text you produce: blog posts, documentation, reports, plans, commit messages, PR descriptions, code comments, chat answers, summaries, subagent instructions. They are not an instruction to go edit existing files or other people's text.

Goal: natural language, the way a normal person writing today would put it. Not stylized, not formal, not AI-flavored.

1. No em dashes.
2. No "it's not X, it's Y" constructions, including the variants "X rather than Y", "not A, but B", and paired sentences like "That means A. This means B."
3. No frases de efeito: punchy closers, rhetorical flourishes, dramatic one-liners, metaphors used for effect.
4. No redundancy: never restate the same fact in different words.
5. No repetition: do not make the same point again in a later section.
6. Clarity, short, direct.
7. Do not over-explain.
8. Content is written for learning purposes.
9. No aphoristic closers. Never end a paragraph or section with a short summarizing one-liner ("The rest is mechanics.", "That is the whole thing.", "Silence means it did."). End on the last technical fact.
